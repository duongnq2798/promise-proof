# Report design direction

References visually inspected on 2026-10-13:

- [Linear](https://linear.app/): compact workspace navigation, restrained neutral surfaces, strong information hierarchy and progressive disclosure.
- [Vercel Geist](https://vercel.com/geist): typography, high-contrast neutral foundations, fine dividers and consistent small controls.
- [Raycast](https://www.raycast.com/): focused presentation and careful spacing. Its public website was reviewed as a secondary reference.

These are references, not copied layouts, logos or claims of affiliation.

The report should feel like a focused verification workspace. Put verdict, assertion counts and relevant evidence in the first screen. Present the workflow as concise expandable rows. Keep the failed observation visible; retain full expected and observed data behind native disclosure controls. Place preconditions, machine identifiers and diagnostic records below the primary review surface.

Use a graphite dark palette and a warm neutral light palette, with restrained mint branding and semantic red/amber states. Embed licensed Geist typography locally so reports remain self-contained and work offline. Expose accessible System/Light/Dark choices without JavaScript. Use real anchor links and native details controls rather than decorative buttons.

Verification boundaries remain unchanged: every row retains its actual status, blocked assertions remain NOT_VERIFIED, screenshots never substitute for API evidence, and the HTML is generated from the recorded result without model judgment. Test the expanded failure, long observations, empty evidence, both themes and mobile layout.
