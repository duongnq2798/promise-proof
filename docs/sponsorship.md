# Support PromiseProof maintenance

This is a maintainer setup guide, not a live funding page. The owner has a PayPal account; receiving eligibility and a Ko-fi connection still need to be checked by the owner. No sponsor account, payment or funding URL has been created by this project.

## Owner setup: Ko-fi with PayPal

1. Create your page at [Ko-fi](https://ko-fi.com). Choose an available handle and use **PromiseProof** as the display name. Availability of any proposed handle has not been checked.
2. Open **Settings → Payment**, choose PayPal and complete the connection directly with PayPal. Ko-fi supports PayPal alone and sends support directly to the connected account. You do not need to add Stripe for this route. [Official payment guide](https://help.ko-fi.com/hc/en-us/articles/115003980093-How-do-I-get-paid).
3. Check the account's mode. For simple one-time tips, Ko-fi Free currently has a 0% platform fee; Standard adds 5% to those tips. Monthly tips and memberships carry 5% in either mode, and PayPal processing fees are additional. New accounts can start with extra features enabled, so inspect the setting rather than assuming it is off. [Official fee guide](https://help.ko-fi.com/hc/en-us/articles/360002506494-Does-Ko-fi-take-a-fee).
4. Add the profile copy below. Start with one-time support; add recurring benefits only when you can maintain them. Select a supported receiving currency after checking your account's conversion fees.
5. Open the public page while signed out. Check the project name, profile copy and that PayPal is offered; inspecting checkout does not require making a payment. Only an actual received payment establishes successful receipt.
6. Send the public Ko-fi page link to the repository maintainer workflow. Do not share passwords, PayPal email, tokens, bank details or payment screenshots containing private data.

## Suggested profile copy

**Title:** Help maintain PromiseProof: real evidence for software outcomes.

PromiseProof runs specified workflows in a real browser and combines UI observations with independent test API checks. Its offline report shows what passed, failed, or could not be verified.

Your support helps fund maintained browser compatibility, clearer first-run guidance, reproducible examples and issue fixes. The core remains free and open source.

One-time tips and optional recurring support are welcome. Sponsorship supports maintenance; it does not buy a passing verdict or a guaranteed support response time.

## Repository integration after the link is confirmed

Use the confirmed handle in `.github/FUNDING.yml` and the same verified public link in README. GitHub supports Ko-fi funding entries on the default branch. [GitHub funding documentation](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/displaying-a-sponsor-button-in-your-repository).

No active funding file should use a guessed handle. A visible Sponsor button establishes navigation, not receipts or sponsor demand.

## Adoption after onboarding is available

- Keep one working runtime command and a separate skill-install command visible in README.
- Demonstrate the intentional defect with its actual report: UI success, missing persistence, blocked downstream check.
- Prepare short launch drafts and an optional consenting pilot; publishing posts or contacting people requires the owner's explicit direction.
- Track observed first reports, repeated use, reported blockers and actual support separately. Stars, skill installs and package downloads do not prove useful verification or recurring use.

These are recommendations. No outside-user session, growth metric, willingness-to-pay result or promotion is claimed.
