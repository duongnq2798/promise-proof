# PromiseProof v0.1.0-preview.2

This GitHub development preview adds an installed `demo` command and runnable `init --example` templates. Download the tarball and checksum from this release; the provisional package remains promiseproof-local 0.1.0, with npm publication and stable branding pending.

## Install

Requires Node.js 22.12 or newer and npm. Download `promiseproof-local-0.1.0.tgz` and `SHA256SUMS.txt`. Compare the tarball SHA-256 to the checksum before installing; this is a transfer check, not a digital signature.

In a new test-project directory:

```sh
npm init -y
npm install /absolute/path/to/promiseproof-local-0.1.0.tgz
npm exec playwright install chromium
npm exec --offline -- promiseproof demo
```

Use the actual downloaded path. On Linux, Chromium installation may need `--with-deps chromium`. Keep the demo terminal running; its synthetic in-memory fixture listens only on http://127.0.0.1:4173 and stops with Ctrl+C.

In a second terminal in that project:

```sh
npm exec --offline -- promiseproof init --example simple-form
npm exec --offline -- promiseproof doctor --spec .promiseproof/example.json
npm exec --offline -- promiseproof verify .promiseproof/example.json
```

The saved-contact example should PASS with exit 0. Open the printed report.html path. Doctor readiness is setup-only and never substitutes for verify.

## Catch the deliberate defect

In a separate fresh directory, install the same tarball and select `init --example failing-workflow`. Keep the demo running, then use the same doctor/verify commands. Expected result: UI PASS, persistence FAIL, dependent NOT_VERIFIED; verify exits 1. The expected persistence value remains intact.

`init --example invitation-flow` runs sender/recipient/membership checks with expected exit 0 in another fresh directory. It uses a controlled local link API; real email delivery is unverified.

Init preserves existing files, so selecting a new example does not replace an existing contract. Start in a fresh directory for each example. If using `demo --port 4174`, pass `init --base-url http://127.0.0.1:4174 --example simple-form`; match both spec and policy to the same authorized origin. Plain init keeps the starter for your own app: edit its actual acceptance criteria before using it.

## Evidence and limits

The candidate is checked through real Chromium, full quality gates, independent review, generated-example consumer smoke and six OS/Node CI jobs before publication. Exact executed results are in docs/verification.md. External-user usability remains unverified.

Chromium/JSON only; no hosted service, real email delivery, redirect authentication or certification. Use disposable authorized test data; keep credentials in references and follow screenshot/trace restrictions. Reports remain offline and preserve recorded verdicts. Use the repository's private vulnerability reporting form for security issues.
