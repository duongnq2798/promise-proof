# Security policy

This is an unreleased 0.1 development MVP. There is no production service or security SLA. Use authorized test environments and review [security boundaries](docs/security.md).

Do not open public issues containing credentials, private screenshots, traces, raw tokens or exploitable live targets. Before a public repository exists, contact its owner through an established private channel. No private reporting address is configured; one must be established before publication. Once available, prefer the repository's private vulnerability reporting feature.

Provide version, platform, a minimal synthetic reproducer, expected boundary, observed violation and sanitized evidence. Keep sensitive bundles local until a private channel is agreed.
