# PromiseProof working agreement

## User preference

The user explicitly requests Superpowers for ongoing product development and daily planning. Apply this preference to every development task in this repository. Communicate with this user in Vietnamese unless they request another language.

## Superpowers workflow

- Read `superpowers:using-superpowers` before acting and use the applicable Superpowers skills for discovery, planning, implementation, debugging, review and verification.
- Resolve skills from the current available-skills catalog rather than hardcoding a plugin version or installation path.
- Follow the applicable skill stages. Existing user authorization and explicit user instructions take precedence; do not ask for authorization that has already been provided.
- Daily product prioritization does not itself authorize implementation of every proposed feature. Keep proposals, approved work, completed work and verified results distinct.
- Read `ARCHITECTURE.md` before product changes and update it when architecture changes.

## Prioritize help for users

- Start with a concrete user problem, affected workflow and observable improvement. Prioritize severity, how many users may be affected, evidence confidence, and effort.
- Put blocked first use, misleading results, lost evidence and security defects ahead of feature breadth or cosmetic changes.
- Continue improving design and accessibility using relevant current references; keep real evidence and verdicts intact.
- Prefer clear onboarding, actionable troubleshooting, reproducible examples and accessible offline reports.
- Separate observed facts, assumptions and recommendations. Do not invent feedback, usage numbers, customer interviews or test results.
- Define success before implementation. Verify the affected user journey, preserve deterministic verdicts and report limitations accurately.
- Do not contact users or publish, deploy or send external messages without the required user authorization.

## Daily planning

- Follow `docs/daily-product-planning.md` and inspect the latest daily plan before creating a new one.
- Review project changes, relevant checks, documented limitations and any user feedback that is actually available.
- Keep at most three actionable priorities. For each, state the user problem, supporting evidence, proposed work, acceptance criteria and dependencies.
- Carry unfinished priorities forward deliberately. Change priority only when new evidence or the user's direction supports it; avoid repeating completed work.
- Save the plan in `docs/superpowers/daily/YYYY-MM-DD.md` using the Asia/Bangkok date. Future feature implementation plans use the relevant Superpowers planning workflow.
